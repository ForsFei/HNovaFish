# HNova Fish · 随手读

一个只读的 VS Code 贴吧 / 知乎阅读插件。原生侧边栏配合编辑器正文，跟随 VS Code 主题，不需要后端服务。

## 安装和使用

0.1.37 搭配浏览器扩展 0.1.6 支持新版贴吧滚动续读，正文底部点击“加载更多楼层”，在专用标签页滚动取得后续楼层并去重合并。旧正文缓存会重新读取。暂未取得后续内容时保留已读楼层，可再次尝试；安全验证仍需手动完成。

知乎个性化推荐和贴吧首页推荐每批目标 30 条，数量不足时按服务器游标补取（最多 4 页），按帖子 ID 去重；平台无更多内容或后续请求失败时保留已获取的推荐。刷新仍替换上一批，不无限追加。

老板键默认小键盘数字 0，按下切换到 VS Code“输出”面板，保留侧栏布局，并取消尚未完成的文章切换，避免延迟响应重新打开阅读；快捷键可在键盘快捷方式中修改。

在设置中搜索 `hnovaFish.readerPosition`，可选择右侧栏（right）或下方面板（bottom）。下方面板采用帖子目录、正文、工作区问题三栏布局，拖动两条分隔线调节宽度并自动保存；工作区问题是最近一次渲染时的真实诊断快照；目录可直接切换当前列表中的帖子，正文与工具栏对齐限宽。工具栏可收起或展开目录，并记住状态及栏宽。修改后立即切换，保留当前文章和已加载评论，中间编辑器继续保留。

### 贴吧浏览器协同（自动重连）

0.1.28 需要配套扩展 0.1.6。更新时将 `browser-companion` 文件替换到 Edge 原加载目录，在 `edge://extensions` 点击该扩展的“重新加载”，关闭旧连接页，再打开新连接页并配对一次。

1. 在 Edge 地址栏打开 `edge://extensions`，开启开发人员模式，选择“加载解压缩的扩展”，选中固定目录中的 `browser-companion` 文件夹。可运行 VS Code 命令 **HNova Fish: 打开浏览器配套扩展文件夹** 找到随包文件。
2. 首次运行 **HNova Fish: 连接贴吧浏览器**，在 Edge 配套连接页粘贴自动复制的地址并点击“连接”。首次使用或遇到验证时，点击“打开贴吧并登录 / 验证”，手动完成登录或验证。
3. 保持连接页和专用贴吧标签页打开。以后重载、关闭后重新打开 VS Code 时会恢复同一个本机连接，Edge 页自动重试，无需重新复制地址。重新打开配套连接页也会读取已保存地址并自动连接。
4. Edge 页的“断开”会停止自动重连并忘记该页保存的地址。VS Code 命令 **HNova Fish: 断开浏览器并使用直接请求** 会关闭服务并撤销已保存配对；需要重新配对时先运行此命令，再运行“连接贴吧浏览器”。

配对信息在 VS Code SecretStorage 中保存，Edge 地址保存在配套扩展自身的隔离存储中，不会写入仓库或 VSIX。服务仅绑定本机 `127.0.0.1`，首次分配随机端口后记住该端口和令牌，重载后仍限制原配对扩展来源。若同一配置的另一个 VS Code 窗口占用了该端口，会提示关闭冲突窗口；不会自动改端口导致浏览器失配。浏览器中的 Cookie 不会传给插件。协同模式不需要手动复制 Cookie；平台验证仍需在浏览器完成。此前用户已确认列表和正文能正常读取，自动重连通过扩展宿主重启模拟和真实本机 HTTP 桥接测试。

正文先显示，缺失的楼中楼预览后台补充；新版页面已有预览时不再请求旧接口。读取等待正文 DOM，不等待广告等子资源全部完成；后台连接使用长轮询。

1. 运行 `npm install`、`npm run package`，生成 `hnova-fish-0.1.43.vsix`。
2. 在 VS Code 扩展面板右上角菜单选择 **从 VSIX 安装…**，选中该文件。也可以运行 `code --install-extension ./hnova-fish-0.1.43.vsix`。
3. 打开活动栏的鱼形图标，展开知乎个性化推荐、知乎热榜、贴吧首页推荐或常用贴吧，点击帖子阅读。
4. 标题栏 `+` 添加贴吧，链接按钮可直接输入帖子链接。通过 VS Code 设置中的 `hnovaFish.forums` 修改、删除关注的贴吧。
5. 点击帖子后正文显示在原生右侧栏，中间的代码编辑器继续保留；切换帖子复用同一个阅读侧栏。拖动中间分隔线可调整阅读宽度。
6. 正文工具栏可收藏、刷新正文或查看原文。下方面板的「刷新列表」与目录底部的按钮共用同一个刷新操作。工具栏为单行，空间不足时可横向滚动左侧控件，右侧保留上一篇和下一篇。`Ctrl+Alt+;`（macOS 为 `Cmd+Alt+;`）隐藏右侧栏，阅读内容保留。在命令面板运行 **HNova Fish: 打开右侧阅读栏** 可再次展开，也可以点击右侧的“随手读 · 阅读”容器图标。
7. 点击列表中的 **浏览其他贴吧…** 或顶部搜索按钮，输入准确吧名（例如“电影”）或贴吧列表链接，再选择“临时浏览”或“永久加入侧边栏”。前者只保留在当前窗口，后者写入常用贴吧并在重启后保留。临时列表下方的 **收藏这个贴吧** 将其加入常用贴吧，**关闭临时浏览** 移除临时入口，不影响收藏。

阅读工具栏的 **亮度** 滑块可在 70%–130% 调节正文、评论、目录、工具栏和工作栏的文字颜色，拖动时实时预览。点击百分比恢复主题默认的 100%。亮度会自动保存，也可在设置中修改 `hnovaFish.fontBrightness`。

正文默认折叠图片。设置 `hnovaFish.showImages` 可以开启已知平台图片域名的图片。阅读工具栏的 **A− / 字号 / A+** 直接减小、恢复默认或增大字号，范围 12–24 px，正文和评论一起调整；也可通过 `hnovaFish.fontSize` 设置。字号会保存，优先修改现有工作区的字号覆盖设置，否则保存为全局设置。调整字号不重新请求推荐、正文或评论。正文支持选中文本、滚动阅读，切换到另一篇帖子或文章时回到顶部；同一篇内容内加载评论、翻页和调整字号保留当前位置，侧栏隐藏期间也保留页面和滚动位置。重载 VS Code 后重新选择帖子即可读取正文缓存。侧栏位置由 VS Code 管理，如果手动移动过，可通过容器右键菜单调整位置。

## 阅读快捷键与老板键

- 阅读工具栏的「上一篇」「下一篇」与方向键共用列表顺序，到列表首尾时对应按钮置灰。阅读栏或左侧随手读列表获得焦点时，`←` 上一篇、`→` 下一篇，按点击来源列表的顺序切换，支持热榜、推荐、贴吧、收藏与历史；到首尾停止，不自动刷新或跨目录。从列表打开文章后自动把焦点移入阅读栏。单独粘贴的链接没有列表顺序。切换文章仍从顶部开始。阅读页实际焦点通过 iframe 焦点事件同步，避免只依赖 VS Code 的视图焦点判断；从指定回答查看同一问题的其他回答后仍保留原列表顺序。
- `NumPad0`（小键盘数字 0，需开启 Num Lock）是老板键，在当前 VS Code 窗口切换到输出面板。正在加载的文章不会随后自动打开阅读栏。上排数字 `0` 保留正常输入功能。原 `Ctrl+Alt+;` 继续只隐藏右侧阅读栏。
- 修改快捷键：运行命令 **HNova Fish: 设置阅读快捷键和老板键**，或在侧栏标题“…”菜单选择同名命令，进入 VS Code 原生“键盘快捷方式”设置。可分别修改上一篇、下一篇、老板键；没有小键盘也可改成其他组合。左右箭头默认仅在随手读列表或阅读栏生效，代码编辑器继续保留正常光标移动。
- 老板键保留阅读内容，点击列表帖子或运行 **HNova Fish: 打开右侧阅读栏** 可恢复阅读。快捷键仅在 VS Code 窗口内生效。

## 分发给其他人

只需发送 `hnova-fish-0.1.43.vsix`，无需附带源码、`dist` 或 `node_modules`，对方也不需要安装 Node.js/npm。

- 需要桌面版 VS Code 1.143 或更新版本，以及可访问知乎/贴吧的网络。
- 对方在扩展面板右上角菜单选择 **从 VSIX 安装…**，选中安装包，按提示重载窗口。
- Cookie、收藏、阅读历史和个人设置不在安装包中；对方需自行配置本人的 Cookie，必要时填写同一浏览器的 User-Agent。
- 平台登录验证、设备校验或接口变更仍可能影响使用。
- 工作区只保留当前版本 VSIX，旧版安装包可删除；源码通过 Git 历史管理。VSIX 不提交到源码仓库，本地可用 `npm ci`、`npm run package` 重新生成。

## 当前范围

- 贴吧首页推荐：携带 `is_new=1`、`tag_id=like` 读取贴吧首页推荐接口，并保留下一批的帖子游标，必要时回退到首页网页，使用已有贴吧 Cookie 和 User-Agent 设置。底部“刷新推荐 · 换一批”替换当前批次，不无限追加。接口返回空内容或受安全验证限制时显示真实错误，不用其他贴吧帖子充当首页推荐。实际结果由贴吧决定，不保证与浏览器首页同时一致。
- 其他贴吧浏览：支持输入准确吧名或带 `kw` 参数的贴吧列表链接，输入后可选择临时浏览或永久加入侧边栏；临时浏览不自动修改常用贴吧，支持随后收藏，取消选择不会修改浏览目录。临时入口只保留在当前 VS Code 会话中，收藏通过设置持久化。
- 知乎热榜底部可单独“刷新热榜”；贴吧目录底部“刷新帖子列表”重新获取首页并替换旧列表，不追加。刷新失败保留原列表。
- 贴吧：关注贴吧的帖子列表、帖子正文和逐页加载主楼回复。正文先读取桌面版，失败或没有楼层时尝试移动版；适配桌面楼层、独立正文节点、移动版楼层及旧 WAP 楼层。翻页仅跟随同一帖子同一种页面格式的链接，避免猜测页码导致错页。失败时分别显示桌面版、移动版的原因。
- 贴吧楼中楼：正文加载时用整页接口获取预览，每层默认显示最多 3 条；没有回复时不显示区域，剩余回复点击“展开剩余 N 条回复”按需分页、去重，失败可重试。不知道总数时显示“展开更多回复”，不猜测条数。使用本机贴吧 Cookie 与 User-Agent，预览受限时保留正文，已知有回复的楼层保留展开入口。预览随正文缓存保存，展开后的完整回复只在当前阅读页内存中；旧版缓存首次打开会尝试更新。移动版后续页无法可靠转换页码时跳过整页预览，可见内容以平台返回为准。
- 知乎个性化推荐：使用已保存的知乎 Cookie 请求首页推荐接口，按平台返回顺序显示回答、文章和问题，并标注内容类型、作者；跳过已识别广告和暂不支持的视频等内容。底部“刷新推荐 · 换一批”使用平台返回的分页获取下一批，并替换当前列表，不累加旧推荐；没有下一页时重新获取首页推荐。换批失败保留当前列表，工具栏刷新重新获取推荐。没有配置 Cookie 时提示登录，失败时不使用热榜替代推荐。实际推荐结果由知乎决定，不保证与浏览器同一时刻的首页完全一致。
- 推荐回答打开的是指定回答，正文工具栏“其他回答”可进入该问题的多回答阅读页。专栏文章本身没有问题回答列表。
- 知乎热榜：保留单独的热榜问题列表。问题页展示多个回答，包含回答目录、作者、赞同数（平台返回时）、已加载数量，以及平台返回时的总回答数。每条回答可以折叠，通过目录跳转。
- 知乎回答每次请求最多 10 条，底部“加载更多回答”按平台返回的分页继续追加，自动去重。指定回答链接仍只展示指定回答，专栏链接展示一篇文章。优先读取正文接口，接口失败时回退到网页解析；回退时明确提示内容可能仅有一条，可再次尝试加载更多。长数字问题 ID 保持原始精度。
- 本机收藏（最多 200 条）、历史（最多 100 条）、正文缓存（最多 30 篇且总计约 6 MB）。再次打开先读缓存，工具栏重新加载可获取最新内容。
- 清空历史命令同时删除正文缓存，保留收藏。
- 知乎评论：回答或文章下方点击“查看评论”，按需加载、刷新或继续分页；显示评论作者、正文和赞数。评论下方的“展开全部回复”请求该评论的楼中楼，支持“加载更多回复”、去重、折叠和失败重试，保留“谁回复谁”的关系。知乎评论和贴吧楼中楼读到末尾时会显示已加载提示。实际可见回复以当前登录权限及平台返回为准。无法识别回答 ID 的网页内容不会显示评论入口，可尝试重新加载正文。评论和回复只保留在当前阅读页内存中，不写入正文缓存。
- 仅阅读；点赞、发表评论等操作在原文中进行。知乎答案排序使用平台默认顺序，目前不支持切换排序。推荐加载使用只读 GET 请求，不额外发送点赞、关注或阅读行为上报；服务器仍会看到访问请求。

## 平台访问限制与登录

0.1.20 起，贴吧请求会接收响应中的 Set-Cookie，按域名、路径和有效期管理后续会话，更新的 Cookie 使用 SecretStorage 保存。正文、列表、预览与楼中楼共用会话，请求串行发送且开始时间至少间隔 800 毫秒。重新设置或清除贴吧 Cookie 会重置该会话。此改动不代表已解决所有 HTTP 403，平台的浏览器验证仍需在原站完成。

如果贴吧返回回复数量但缺少楼层 ID，会提供“重新识别并展开回复”：重新获取正文，准确匹配原楼层后再加载楼中楼。仍无法定位时提示查看原文，不把楼层序号当作回复 ID。

**匿名访问不保证可用。** 开发机器实测知乎热榜返回 HTTP 401，贴吧会返回 HTTP 403 或安全验证页面。插件识别这些结果并提示，不使用演示数据替代。解析测试、扩展宿主测试通过不代表平台线上接口始终可访问。

需要登录时，先在本人浏览器登录对应平台，打开开发者工具的 Network，刷新网页，选择该平台的请求，从 Request Headers 复制 **Cookie 的值**。在命令面板运行 **HNova Fish: 设置或清除登录 Cookie**，选择平台并粘贴。不要粘贴 `Cookie:` 前缀，也不要把 Cookie 写到源码、设置或 issue 中。

Cookie 使用 VS Code `SecretStorage` 保存。运行在远程扩展宿主时，其具体保存位置和保护方式由 VS Code 环境决定。每个平台的 Cookie 仅发送到该平台预设 HTTPS 域名；请求不自动跟随重定向。原文按钮使用系统默认浏览器，浏览器登录状态不会自动同步进插件。

**Cookie 不能保证解除反爬或设备校验。** 如仍受限，先在浏览器完成验证后重试；依然失败时可查看原文。正文解析依赖平台当前页面结构，未来可能需要更新适配器。

贴吧列表会先请求桌面版，失败后尝试移动版，并发送贴吧来源与中文语言标头。仍失败时，点击列表中的“加载失败 · 点击查看原因”，可看到两次请求的 HTTP 状态及 Cookie 是否含百度登录字段的提示，不显示 Cookie 的值。含登录字段不代表登录仍有效。

若同一浏览器可浏览贴吧，但插件仍失败，可以从浏览器该请求的 Request Headers 复制 `User-Agent` 的完整值，在 VS Code 设置搜索 `hnovaFish.tiebaUserAgent` 并填写（不包含 `User-Agent:` 前缀）。此设置只作用于贴吧。百度可能还校验浏览器环境、设备与网络，因此同样的 Cookie 和 User-Agent 仍可能被安全验证拦截。请勿把 Cookie 发到 issue 或聊天中。

## 本地开发

需要 Node.js 22+、VS Code 1.143+（使用原生 `secondarySidebar` 容器；已核对当前本机版本 1.143.1 支持）。

```powershell
npm install
npm test
npm run package
```

在 VS Code 打开项目，按 F5 启动扩展开发宿主。`.vscode/launch.json` 已配置编译任务。

在真实扩展宿主中运行集成测试（使用固定响应，不依赖平台联网）：

```powershell
npm run compile
code --extensionDevelopmentPath="$PWD" --extensionTestsPath="$PWD/dist/test/host.js" --user-data-dir="$env:TEMP/hnova-fish-test-profile" --extensions-dir="$env:TEMP/hnova-fish-test-extensions" --disable-extensions --skip-welcome --skip-release-notes --disable-workspace-trust
```

`src/providers.ts` 负责平台请求和解析，`src/render.ts` 负责白名单净化与阅读器，`src/readerScript.ts` 负责由 TypeScript 检查的阅读页交互脚本，`src/extension.ts` 负责 VS Code 交互及本机持久化。测试覆盖 DOM 中按钮实际点击、打包脚本执行及模拟扩展宿主中的操作结果，不依赖线上知乎请求。

正文中的脚本、表单、事件属性和不安全链接会被删除；Webview 使用 CSP 禁止正文主动执行脚本。图片默认关闭，开启后由 Webview 直接请求图片域名。收藏、历史和正文缓存保存在扩展本机存储中，不上传到任何自建服务。

首页接口参数适配参考：[Tieba Remix 作者源码](https://github.com/0x0b1ade/Tieba-Remix)。0.1.12 已使用本插件 Providers 在真实匿名请求中验证获取到 10 条首页帖子；登录用户的返回结果仍由贴吧决定。
